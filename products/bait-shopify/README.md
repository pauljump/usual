# Bait for Shopify

**Give the scrapers a catalog full of nothing.** A native Shopify app with a
merchant-enabled theme embed, a controlled catalog maze, private real counters,
and downloadable receipts. This is a development pilot, not a published App Store app.
Bait is registered in Paul Jump's Shopify organization. The existing development
backend is published at `https://bait-shopify.polyfeeds.dev`; development-store installation is pending the access grant.
No paid service or plan upgrade was activated.

## Product contract

The user is a Shopify merchant curious about crawlers exploring their storefront.
The immediate benefit is seeing actual requests to deliberately fictional catalog
pages, with a shareable receipt. The underlying business hypothesis is a useful
network of observed bot behavior; buyer demand and a permitted data-licensing model
remain unknown. Shared-network reporting and data resale are absent from this MVP.

The first workflow lives in Shopify Admin: install → open Bait → enable the theme
app embed and save → acknowledge recording → turn on traps → view observations.
It uses official Shopify React Router authentication, App Bridge, Polaris web
components, session storage and authenticated app proxies. Only `write_app_proxy`
is requested. No product, order, customer or theme-read/write scopes.

This directory stays in Usual's canonical repository while the integration shares
Bait's product development. It is a separate runtime package, not part of the Python
release or the existing Cloudflare Worker. Publication and an independent product
repository can be reviewed when it graduates.

## What is implemented

- Native embedded Admin page with setup, pause/enable, no-count preview, honest empty
  state, automatic visible-tab refresh, recent observations, daily budget, JSON export
  and a downloadable SVG receipt. Nothing counts up in the browser.
- A body-target theme app embed leaves one hidden, non-focusable, nofollow link.
  No browser JavaScript or pixel. Nothing auto-fetches the bait on behalf of a shopper.
  The theme editor displays a setup note; customers do not see that note.
- Shopify proxies `/apps/bait/catalog` and deeper paths to this app's `/proxy` route.
  Custom proxy prefixes are taken from Shopify's signed query; the embed's path
  setting must be updated if a merchant customizes that URL.
- HMAC-protected links carry a random journey, deterministic branch, depth and expiry.
  The same signed URL generates the same fictional records and child links while
  valid. New entrance requests create new journeys. Child URLs expire after seven
  days; depth is capped at 1,000,000 and each response contains 12 records.
- Quick JSON catalog and HTML archive responses. No product schema, checkout links,
  live discounts, Shopify product writes or expensive model calls. HTML says items
  are archived and cannot be purchased. Responses request no indexing/caching.
- Accepted GET counters: requests, generated records, generated bytes, depth-two-plus
  requests and deepest requested level. HEAD/invalid/disabled/preview requests do not
  count. Recording commits before returning loot; errors return 503, never fake zeros.
- Tenant-isolated SQLite storage; explicit merchant activation starts disabled.
  Per-store/day (2,000) and app/day (20,000) recording budgets are reserved atomically.
  At the cap, bait endpoints return 429; real Shopify routes are not intercepted.
- A maximum 200 trace rows per store, with seven-day report visibility and hourly
  indexed retention cleanup in the production runner. Aggregate totals survive
  retention. Quota buckets older than three days are deleted. This is not a provider
  billing cap: HTTP requests still consume the host/transport's resources.
- Signed uninstall and privacy webhooks. Uninstall/shop-redact erase the installation's
  app records and stored sessions. Customer requests are acknowledged without a
  customer lookup because visitor/customer identity isn't collected.

## Measurement boundaries

These are **trap requests**, not unique bots, proof of malicious intent, verified
scrapes, CPU usage or money lost. Humans and retries can count. Generated records
may repeat; this is not a count of unique products. A link chain may be shared among
clients and does not establish one operator. Client families are self-declared UA
categories, not verified identities. No fake time-wasted counter is supplied because
Shopify's proxy delivery/streaming behavior has not been measured.

The app cannot intercept arbitrary `/.env` probes or inspect all storefront traffic.
Coverage depends on the embed being activated and clients actually following its
link. Theme activation is merchant-confirmed; it is not automatically verified.
Changing the embed removes the discovery link; pausing in Admin also closes existing
trap links. No evidence of useful unsolicited Shopify interactions exists yet.

## Data contract

Trap records contain time, kind, depth, generated records/bytes, a random journey
marker, recipe version and coarse declared client family. They do not retain raw
IPs, raw UAs, request bodies, query strings, cookies, customer IDs or real catalog
content. No ASN/country/operator identification is claimed.

Connection sessions contain Shopify access/refresh tokens and any merchant identity
fields Shopify's official session adapter needs. They are private runtime data,
separate from the downloadable observations. Runtime SQLite must be outside the
repository, protected and backed up as sensitive application data. The production
runner omits access logs and suppresses request/error details; a future tunnel or
reverse proxy must also avoid recording full proxy URLs and query strings.

The installed app has no telemetry destination or opt-in network button. Merchant
activation authorizes this store's private score only; it is not a license to resell
merchant data. Revisit Shopify terms and the merchant agreement before implementing
a contribution or licensing product. A complete public privacy policy, operator
contact/support details and App Store review remain launch work.

## Local development

Node 22.22+ (tested 22.22.2), npm, and Shopify CLI for connected development.
The app follows Shopify's official React Router template at commit
`e548c959eb00460f7141d42bd694cd50769c5e3e`; its MIT license is retained in LICENSE.md.
`package-lock.json` pins the installed dependencies. API version: 2026-07.

```sh
cd apps/bait-shopify
npm ci --ignore-scripts
```

Runtime configuration is loaded through the portfolio vault runner from
`/Users/mini-home/.secrets`, never from a project `.env` file:

| Name | Meaning |
| --- | --- |
| `SHOPIFY_API_KEY` | Registered app's public client ID |
| `SHOPIFY_API_SECRET` | Registered app's secret, kept in the vault |
| `SHOPIFY_APP_URL` | Reviewed canonical HTTPS application origin |
| `DATABASE_URL` | `file:/absolute/private/path/bait-shopify.sqlite` outside the repo |
| `PORT` | Optional loopback port; default 3087 |

With those variables loaded, `npm run setup` initializes the private DB file,
generates Prisma and applies the checked-in migration. Initialization does not
seed counts. `npm run build` compiles the app and `npm start` runs the loopback-only
server. `npm run maintenance` performs the same bounded retention cleanup manually.
Production start also runs cleanup at startup and hourly; there is no paid agent job.

`shopify.app.toml` and the CLI-selected `shopify.app.development.toml` reference the
registered Bait client `27297a7de66ce583214e00bb0dcfc8da`. Keep these aliases synchronized.
They select `draft-documents-test-store.myshopify.com` and the published canonical origin
`https://bait-shopify.polyfeeds.dev`. The public login page has returned HTTP 200. Credentials
were retrieved through Shopify CLI directly into the vault without printing values.

The fleet registry contains an **online** `bait-shopify` entry. Runtime prerequisites
and the database migration have been checked. See [the deployment review](deploy/REVIEW.md)
and [the declaration](deploy/web.json) for exact scope and remaining installation checks.
`npm run dev` can publish a temporary tunnel; do not use it as an alternative to the
reviewed canonical deployment. Shopify CLI 4.8.2 native build and Theme Check passed.

## Offline verification

```sh
# Generates local code, no Shopify account/API calls.
npx prisma generate
npm run typecheck
npm test
npm run test:server
# Also validates/bundles the theme extension using Shopify CLI.
SHOPIFY_CLI_NO_ANALYTICS=1 shopify app build --config development

# A loopback-only static design preview, not a Shopify-auth bypass.
npm run preview:local
# Or write a self-contained review file under /tmp:
npx tsx scripts/preview.tsx --write
```

Tests use isolated synthetic SQLite databases under `/tmp`. They check real
counter updates, linked deterministic branches, wrong signatures, expired tokens,
cross-store isolation, no-count HEAD/previews, activation, pause, budgets, retention,
data minimization, deletion and database errors. SDK tests run Shopify's actual
proxy/webhook authentication code with synthetic secrets and an outbound-network
tripwire. Live sessions, token exchange and theme rendering still need the development-store installation.
`test:server` builds the production bundles and checks the actual HTTP server with
synthetic credentials, including signature rejection, body limits, private downloads
and omission of sensitive URL access logs. It makes no Shopify API calls.
The design preview uses the real Scoreboard component with a labelled empty fixture
and CSS fallbacks for local inspection. It is not the Shopify Admin iframe.
