# A room with no far wall

[SPITE.md](SPITE.md) is the product contract. The tarpit gives each scanner path
nine more doors: two directory listings and seven kinds of fake file. Each door
has more doors. All links stay on the request's host.

`createBait({ secret, tarpit: true, tarpitSeconds: 120, store })` enables it.
The Worker reads `BAIT_TARPIT=true` and `BAIT_TARPIT_SECONDS=120`; the portfolio
config enables both. The library remains opt-in, preserving existing installations.
`drip` remains the original option for installations without tarpit mode.

## The maze

HMAC of the host, path, and a label chooses each child and fake credential. The
same URL has the same body across requests, visitors and process restarts with
the same secret. Queries do not change the room. No filesystem or tree is stored.
`/_archive/<depth>/<128-bit branch>/<file>` folds the ancestry into a fixed-size
branch rather than growing the URL with each step. Nine children per room give
exponentially growing breadth; the 30-digit depth field is a practical rather
than mathematical infinity. GETs stream; HEADs return headers without creating
measured tarpit traffic. Ordinary pages pass through.

Stable fake credentials can still come back through the existing trip detection.
D1 stores a hash and the first observed scrape for each maze credential. Repeated
scrapes of the same URL therefore share that first attribution; they cannot
identify which of several readers reused it. Old sealed credentials still work.
Without a store, maze generation works but stable-credential attribution does not.
Maze mode always generates its own fake AWS key, even if an installation has an
external AWS canary configured for the original one-shot mode.

## The score

- `timeWasted.milliseconds` / `.seconds`: monotonic elapsed response-stream time,
  summed over connections. Concurrent connections each count their observed time.
- `computeBurned.bytesGenerated`: only generated bytes actually handed to the
  response stream, not the full size of an abandoned response.
- `computeBurned.requestsServed`, `.deepRequests`, `.deepestLevel`: streams with
  emitted bytes, requests to depth 2 or greater, and maximum addressed depth.
  Depth describes the room requested, not proof of visiting every parent.
- The same main totals also appear in `totals.timeWastedMs`,
  `totals.computeBurnedBytes`, `totals.tarpitRequests`, and `totals.deepMazeRequests`.

These are server observations, not TCP acknowledgments or measured client CPU.
Human requests to the fake files count too; Bait cannot prove who is a bot.
No measurements are inferred from old scrape counts. No local previews or
historical imports populate the new production counters.

The stream sends a small chunk about once a second over its configured budget
(default 120 seconds, clamped to 300), respecting consumer backpressure. A deadline
ends a stalled consumer at the budget plus one second of scheduling grace. Abort
and cancel clear the timers immediately. Node middleware also handles socket
closure and write backpressure.

Cumulative checkpoints are saved every 10 seconds and at close/cancel. A D1 batch
adds only the difference from the previous checkpoint and updates the connection
row atomically. Duplicate or out-of-order writes cannot double-count time, bytes,
or requests. An isolate being killed may lose the final interval; the score errs
low. Writes use `waitUntil` so they may finish after disconnect. Stats retain the
existing 60-second database cache, 30-second HTTP cache, and 60-second page poll.
The counter tables are additive and never reset the original leaderboard.

Each request uses one bounded response body; it does not allocate the whole maze.
Each measured connection retains one checkpoint row, and each new file retains
its credential hashes. D1 storage grows with traffic, as do the existing raw logs.
A full two-minute request adds about twelve checkpoint batches, each with two
statements in base mode, plus its served-event writes. Learning adds aggregate
and bounded private-trace writes; see [LEARNING.md](LEARNING.md). Sleeping saves Worker CPU, but Worker
requests, D1 writes and storage still consume the account's quota.

## Verification and publishing

Run `python3 -m pytest -q tests/test_bait.py` for the original scripted client plus
maze determinism, many-level traversal, all file formats, disconnect and abort,
real elapsed time and byte accounting, open-stream checkpoints, duplicate writes,
Node socket closure, and additive upgrade checks. All traffic is local.

Use `node scripts/bait/deploy.mjs` for the read-only deployment plan, then
`node scripts/bait/deploy.mjs --apply` after reviewing it. Credentials come from the
vault described in the project contract. The base maze needs `/_archive/*` on a paths-only zone. The learning
extension adds reviewed probe routes; see [LEARNING.md](LEARNING.md). Do not seed preview counters or issue synthetic live maze
requests to make the public score move. Verify publication through the leaderboard
and its JSON; watch real incoming traffic produce the counters.
